# Agent 响应质量评分标准（Rubric）

本评分标准用于裁判模型（Judge LLM）评估 Agent 回答质量，满分 5 分，涵盖 8 个维度。

## 评估架构（Claim-Level 分解，对齐行业做法）

评估分为两个独立模块：

1. **主观维度评估（6 维）**：由 Judge LLM 直接评估，不依赖参考原文
   - 相关性、完整性、格式规范、分析深度、关键概念覆盖、指令遵循

2. **事实核验（Claim-Level，2 维）**：通过声明级分解验证，需参考原文
   - 忠实度、数据准确性
   - 算法：从回答提取事实声明 → 在参考原文中定位对应段落 → 逐条验证
   - 分数 = 被支持声明数 / 总声明数（映射到 1-5 评分尺度）
   - 对齐 DeepEval FaithfulnessMetric 的行业做法

---

## 1. 相关性（Relevance）

**定义**：回答是否切题，是否针对用户提问的核心意图作答。

| 分数 | 描述 |
|------|------|
| **1 分** | 回答完全偏离问题主题，答非所问，或仅重复问题而未提供实质性回答。 |
| **3 分** | 回答基本切题但存在明显跑题段落，或与用户意图有部分偏差。 |
| **5 分** | 回答精准切题，直接回应问题核心，无冗余或跑题内容。 |

---

## 2. 忠实度（Faithfulness）

**定义**：回答是否基于论文/知识库内容，有无编造、臆测或引入外部未验证信息。需对照参考原文逐项核查。

| 分数 | 描述 |
|------|------|
| **1 分** | 回答包含明显编造内容，与原文矛盾，或引入大量未经验证的外部信息。 |
| **3 分** | 回答大体基于原文，但存在少量无法在原文中验证的推断性描述，且未标注"原文未提及"。 |
| **5 分** | 回答完全基于原文内容，引用准确，无编造。对于原文未覆盖的内容，明确说明而非臆测。 |

---

## 3. 完整性（Completeness）

**定义**：回答是否覆盖问题的所有要点，有无遗漏关键信息。

| 分数 | 描述 |
|------|------|
| **1 分** | 回答严重不完整，遗漏问题的大部分要点。 |
| **3 分** | 回答覆盖了主要要点但遗漏了次要要点或部分细节。 |
| **5 分** | 回答完整覆盖问题所有要点，无关键信息遗漏。 |

---

## 4. 格式（Format）

**定义**：回答的结构、排版是否合规（如 Markdown 章节、分段、可读性等）。

| 分数 | 描述 |
|------|------|
| **1 分** | 格式混乱，无标题、无分段、全文为一整段文字，无任何 Markdown 标记。 |
| **3 分** | 有基本结构但层级不清晰，或分段不合理，排版可读性一般。 |
| **5 分** | 格式规范：使用 Markdown 标题分层，段落清晰，排版专业易读。 |

---

## 5. 数据准确性（Data Accuracy）

**定义**：回答中引用的具体数据（数字、模型名称、数据集规模、参数量、发布时间等）是否与参考原文一致。需对照原文逐一核实。

| 分数 | 描述 |
|------|------|
| **1 分** | 回答中多个具体数据与原文不符，存在明显的数据编造或张冠李戴。 |
| **3 分** | 大部分数据准确，但有个别数值偏差或模型/数据集名称与原文不完全一致。 |
| **5 分** | 所有引用的数据（数字、名称、规模等）均与原文完全一致，无偏差。 |

---

## 6. 分析深度（Depth）

**定义**：回答是否超越简单罗列，提供了有洞察力的分析、归纳或对比。

| 分数 | 描述 |
|------|------|
| **1 分** | 纯罗列原文信息，无任何归纳、对比或分析，等同于复制粘贴。 |
| **3 分** | 有一定归纳总结，但分析较浅，缺少跨章节的关联洞察或对比分析。 |
| **5 分** | 在忠实原文的基础上，提供了有深度的分析——如趋势归纳、横向对比、优劣评价、核心启示等。 |

---

## 7. 关键概念覆盖（Key Concepts）

**定义**：回答是否覆盖了论文的核心概念与关键术语（需对照参考原文识别论文核心概念）。

| 分数 | 描述 |
|------|------|
| **1 分** | 遗漏论文的大部分核心概念，仅涉及边缘内容。 |
| **3 分** | 覆盖了部分核心概念，但遗漏了若干论文重点讨论的关键术语或框架。 |
| **5 分** | 全面覆盖论文的所有核心概念与关键术语，无重要遗漏。 |

---

## 8. 指令遵循（Instruction Following）

**定义**：回答是否精准回应了用户提出的具体问题，而非泛泛而谈或答非所问。

| 分数 | 描述 |
|------|------|
| **1 分** | 完全答非所问，未识别或忽略用户的核心问题，主要篇幅用于回答用户未问的内容。 |
| **3 分** | 部分回应了用户问题，但有明显的内容偏移或遗漏了用户明确要求的方面。 |
| **5 分** | 完全理解并精准回答用户提出的具体问题，回答范围与用户意图高度匹配，未偏离主题。 |

---

## 综合评分说明

- **总分** = 8 个维度分数的算术平均值（保留 1 位小数）
- **每个维度须给出评分理由**：在 `details` 数组中逐项说明打分依据，引用具体例证
- **评分输出格式**：裁判模型须返回 JSON，结构如下：

```json
{
  "relevance": 5,
  "faithfulness": 4,
  "completeness": 5,
  "format": 5,
  "data_accuracy": 4,
  "depth": 4,

  "instruction_follow": 5,
  "average": 4.6,
  "details": [
    {"dimension": "relevance", "reason": "回答精准切题，完整覆盖了用户要求的核心贡献、方法与结论三方面。"},
    {"dimension": "faithfulness", "reason": "整体忠实于原文，但'首篇系统性综述EU 24种官方语言'的表述与原文'first article that presents a comprehensive review'有细微差异，原文未强调'24种'这一精确数字。"},
    {"dimension": "completeness", "reason": "覆盖了论文的背景、贡献、方法、发现、优势与不足，结构完整。"},
    {"dimension": "format", "reason": "Markdown层级清晰，使用了标题、列表、引用等格式元素，排版专业。"},
    {"dimension": "data_accuracy", "reason": "大部分数据准确（如OSCAR规模、BERT参数量），但DeepSeekMoE-V2的具体参数描述在提供的原文截取中未见，无法完全核实。"},
    {"dimension": "depth", "reason": "提供了语言资源分层分析和MoE架构潜力洞察，但缺少对不同语言LLM性能的横向对比实验数据。"},

    {"dimension": "instruction_follow", "reason": "用户要求解读论文，回答完整覆盖了背景、方法、贡献与不足，精准回应了用户意图。"}

```

- **details**：每个维度的评分理由，须引用回答中的具体内容或原文对照作为依据
- **summary**：1-3 句话总结整体评价，指出主要优点与不足
