# 2026-11-11 评估理由幻觉引证修复与评分对象展示对齐

## 问题

Langfuse「Judge 评分」节点中 DeepEval 路由维（相关性等）的评语包含具体引证
（"本文为分……节""请按以下步骤处理""近年来相关研究较多""文件元信息（作者、
发表信息）"），但用户对照页面实际 AI 回答与生成文档发现根本没有这些问题。

取证过程（短语全文搜索）：

| 搜索词 | response.md | document.md | chunks.json（1.2MB 全流含论文原文回显） |
|---|---|---|---|
| 本文分为 / 请按以下步骤 / 近年来相关研究 / 作者 / 发表信息 | 0 | 0 | 0 |

三份产物零命中 → 引证系凭空编造。定性：

- **分数未被污染**：relevance 分数由 DeepEval 基于真实被评内容（AI回答+生成文档
  拼接体）计算，不受影响；只有理由文字被污染。
- **编造环节**：`deepeval_adapter._translate_reasons` 的旧 prompt 要求扩充模型
  "翻译为中文并扩充为详细分析、引用具体内容作为例证"，但扩充模型只拿到英文
  理由文本、从未见过被评内容，为满足"引用例证"指令只能编造。
- **连带展示缺陷**：用户误以为"评分范围只有 AI 回答"——实际评分输入一直是
  【AI回答】+【生成文档】拼接体（`_build_judge_content`），但「Judge 评分」
  EVENT 的"被评估内容"只展示 `ai_response`，显示与实操不一致造成误解。

## 修复

- `core/clients/deepeval_adapter.py`（方案 C）：`_translate_reasons` 改为忠实
  翻译——prompt 与 system 删去"扩充/引用例证"要求，显式禁止添加原始理由中
  不存在的内容、禁止编造引证；docstring 记录取证定性的历史缺陷。
- `core/clients/langfuse_integration.py`（方案 A）：`report_trace` 新增
  `judge_content` 关键字参数，「Judge 评分」EVENT"被评估内容"优先显示裁判
  真实输入，未透传时退回旧行为保证兼容。
- `test_cases/paper_interpret/test_paper_common.py`（方案 A）：
  `_save_full_artifacts` 以与用例主体相同的纯函数 `_build_judge_content(text,
  document_text)` 重建 judge_content 透传（同入参产出逐字一致，q2 编辑重建
  场景由调用方传入的 document_text 保证同源），5 处调用点零改动。

## 验证

- 3 文件 py_compile 通过；`-m offline` 169 passed / 2.17s 无损；
  `paper_interpret` 收集 154 条正常（import 面无破坏）。
- 真实复验（待下轮 INT-001）：①「Judge 评分」被评估内容应显示带
  【AI 回答】/【生成文档】分节标记的拼接体；②DeepEval 维评语应收敛为
  理由本身陈述，不再出现被评内容中零命中的凭空引证。

## 遗留

- 文档侧预算仍为"掐头 8000 字"简单截断（方案 B：前/中/后三段采样未实施，
  长文档结论段仍可能丢失，代价是历史基线可比性波动，待用户决策）。
- DeepEval metric 原始英文理由本身的准确性依赖评估模型能力，本次只消除
  扩充环节的二次编造，不保证上游理由无误。
- 「裁判评语」summary 依赖裁判模型按 prompt 输出，缺失时显示"无"（既有降级）。
