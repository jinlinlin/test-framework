## 问题（为什么要动）

Agent 测试迁移（Phase A 建 `engines/agent_behavior/` 薄壳引擎）存在 4 个硬性崩溃点，
任一不修则 Agent 引擎继承 `BaseEngine` 后立即报错：

1. **P0-2**：`TestMetrics` 只有性能字段（throughput/latency_*/cpu/memory），Agent 引擎
   构造 `TestMetrics(total_cases=…, passed_cases=…, duration=…)` 抛
   `TypeError: unexpected keyword 'total_cases'`。
2. **P0-3**：`BaseEngine.generate_report()`（`engines/base.py:204`）以
   `from_results(plan_name=…, metrics=…)` 调用，而真实签名为
   `(report_id, plan_id, results)`，任何子类继承即抛 `TypeError`。
3. **P0-7**：Agent 输出是 0~1 连续评分 + 阈值判定，`TestResult` 仅有
   PASS/FAIL/ERROR/SKIP 四态，分数只能塞 `details` dict，失去类型安全。
4. **P0-8**：`TestType` 无 `AGENT_BEHAVIOR`，引擎工厂无法路由、配置无法挂载。

**范围裁剪决策**：其余 6 项 P0（P0-1 UI 枚举 / P0-4/5/6 框架自测 / P0-9 Allure 目录 /
P0-10 Reporter 接口）经评审确认不阻塞「Agent 单引擎跑通」，延后处理。否决过的反向
方案（改 enum 值迁就 UI、把计数字段塞 custom dict、改 `from_results` 公开签名）均在
phase-0-fixes.md §1.4/§1.5 说明波及面更大，不采纳。

## 修复（动了什么）

| 文件 | 变更 | 说明 |
|---|---|---|
| `test_framework/core/models/test_metrics.py` | 修改 | 新增 6 个用例统计字段（`total_cases/passed_cases/failed_cases/skipped_cases/errored_cases/duration`），全部带默认值；`to_dict()` 仅当任一非零时写入，避免污染纯性能输出；模块/类 docstring 同步改写定位 |
| `test_framework/engines/base.py` | 修改 | `generate_report()` 改用真实签名 `from_results(report_id=f"{plan.id}-{时间戳}", plan_id=plan.id, results=…)`，`metrics` 随后赋值（`from_results` 不接收该参数） |
| `test_framework/core/models/test_result.py` | 修改 | 新增 `score/dimensions/threshold`（均 `Optional` 默认值）+ `passed_by_score` 属性（评分类走 `score>=threshold`，非评分类回退 `status==PASS`）；`to_dict()` 条件写入 |
| `test_framework/core/models/enums.py` | 修改 | `TestType` 新增 `AGENT_BEHAVIOR = "agent_behavior"` |
| `test_framework/engines/engine_registry.py` | 修改 | 注册 `AGENT_BEHAVIOR` 元数据占位（`version=0.0.0`，`config_schema=config/defaults/agent.yaml` 预占，Phase A 落文件后自动生效） |

设计决策：

- **新增字段全部带默认值 + `Optional`**：旧构造（如 `TestMetrics(throughput=100)`、
  `TestResult(case_id, status)`）零改动继续可用，向后兼容 100%。
- **`to_dict` 条件写入**：评分类字段与计数字段仅在启用时出现在序列化输出里，
  不改变既有消费者（报告层/日志）看到的 schema。
- **`passed_by_score` 判据优先级**：`score`/`threshold` 任一为 `None` 即回退 `status`
  判定——保证二元判定旧用例行为绝对不变（否决过「默认 threshold=0.7」方案，会让旧
  用例语义悄悄改变）。
- **不改 `test_type.json` schema 与 `docs/engines.md`**：Agent 引擎实现尚不存在，
  schema 无内容可校验；留待 Phase A 建引擎时一并补，避免文档先于实现漂移。
- **代码注释不写任务编号**（同日补正）：初版曾在 5 个源码文件的注释/docstring 里写入
  `P0-2/P0-3/P0-7/P0-8` 任务号，已清理——本文档标题与 commit message 承担追溯，
  代码注释只保留自解释的业务语义（读者无需外部文档即可理解）。
